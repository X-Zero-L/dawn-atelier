## 准入步骤

1. 已核对的程序集与元数据哈希组合直接选用对应 profile。
2. 其他组合通过 `native_layout.py` 定位类型表、字段偏移表和 Assembly-CSharp 方法表。检查元数据版本、指针范围、唯一候选和可执行地址。
3. 对比相关类型的字段、方法签名与枚举常量。随后逐个核对 profile 记录的 291 个原生序列化方法字节指纹。
4. 通过后使用同一 schema 家族；资源包按本机当前清单重新解码并核对 CRC。
5. 全部资源步骤成功后才原子写入准备成功记录，中途失败不会沿用旧目录冒充完成。
6. 程序集、元数据或资源清单变化会使准备记录失效，桌面和直接网页启动都要求重新准备。生成方案及导出、应用前还会核对服务启动时的兼容快照，运行中更新游戏也会停止写入。
7. 兼容失败提示包含检测到的资源版本，并区分结构定义变化与序列化代码变化；桌面端在启动准备子进程前也会写入 `prepare.log`，同时清除旧的准备完成记录。

此规则允许无关二进制区域或资源版本变化，不根据日期字符串拒绝。方法代码采用精确指纹，未把指令或地址字段统统忽略；编译重排可能需要重新核对 profile。这是保守的自动兼容范围，不是对任意未来版本的承诺。

资源解码已移除旧版固定 RVA 和固定 bundle 序号。解码常量按元数据中的内容身份查找并校验，配置包按资源名识别。不会把原始密钥、游戏文件或提取图标放入发布包。

## 新版本维护

`research/schema/extract_schema.py` 使用当前程序集的注册表定位，输出原生确认的结构。比较旧映射并审阅变化后，可用 `research/schema/build_compatibility_profile.py` 生成只包含哈希与方法身份的 profile。不能只加入新整文件哈希后宣称支持。

`python -m unittest discover -s tests -v` 覆盖版本日期变化、结构兼容、序列化拒绝、资源清单更新与字段别名。当前安装另外完成了只读原生对照：无关 PE 时间戳变化可通过，序列化代码变化被拒绝；新旧真实存档中的好感修改可逐字节逆向恢复。
